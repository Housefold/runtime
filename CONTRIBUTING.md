# Contributing

Keep changes focused on one runtime behavior or contract. Before changing architecture, module execution, permissions, data retention, or remote access, identify the relevant open decision and propose an ADR for review.

Behavior changes should include focused tests, update the relevant documentation, and describe failure behavior and compatibility impact. Do not include secrets, real household identities, or private device details in issues, logs, fixtures, or screenshots.

The project uses `main` as its trunk. Small commits are welcome; pull requests are optional before the first release.
