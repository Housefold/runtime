## Acceptance mapping

`ha.Sources` serializes local writer ownership and canonical publication. Native
state remains authoritative during Bridge preparation. Two bounded candidates
stage distinct complete views; snapshot barrier and contiguous buffered deltas
must validate before a single generation/revision-zero reset commits. A switch
fences all old and pending writers. No timestamp merge is used.

Selected loss retains stale canonical data and fences the writer. The ordered
client automatically invokes an injected complete fresh native reconciliation.
Candidate failure leaves the selected healthy source unchanged. Delayed native
fallback cannot overwrite a later complete Bridge reentry. A native resync must
open a fresh subscription; its subsequent stream is forwarded via ActiveWriter.
This is an explicit caller obligation, not a claim that cached native data proves
post-failure freshness.

`bridge.PrepareOrdered` provides bounded version-1 subscribe/result/event parsing,
30-second preparation and two-second live deadlines, required barrier/sequence
semantics, gap/epoch rejection and complete fallback. Shared synthetic JSON
fixtures/schema are exercised as wire frames in TestSharedOrderedWireFixture.
Canonical consumers receive only the usual HA state model. No production command
wiring, new credential/listener, Python installation or peer identity authority.
