Acceptance mapping:

- Composition: one launcher-bound IPC reader per child handles health, state subscription, four storage scopes, definitions/schedules, triggers, execution completion/cancellation, action gateway and correlated handover replies. Children are owned before handshake/readiness and cannot become collectable before joining. Only selected ready generations admit new work. Correlated bounded RPCs avoid competing Receive calls; asynchronous bounded authority requests avoid deadlocking the final cutover barrier. Native HA loss is state capability loss, not module/Runtime death.
- Recovery/dependencies: checksummed inventory persists installed/desired/current/previous/pending intent. Offline boot re-verifies signed cached ELF packages at their acceptance time and validates state/router references before admitting work. Enabled modules restore in dependency order with fresh boot/generation authority; disabled/quarantined modules stay stopped. Required exact-version packages, including installed disabled dependencies, prepare together and select in one durable router commit; optional absent dependencies do not block. Failed preparation/final adoption preserves the selected version. No automatic update retry or rollback. Restarts preserve the distinct previous successful version. Interrupted same-executable-byte upgrades are not promoted by digest alone.
- Health/storage: required service/readiness heartbeat, separate UI-health, bounded 1/2/4-second restart budget and terminal quarantine; four isolated logical storage scopes with 64-key/8-MiB quotas and bounded IPC writes. Persistent state handover and retained rollback use distinct stores. Disable/remove retain all data; cloning missing state fails instead of recreating it. Ordinary storage failure fences future writes and exposes storage degradation; uncertain commits/corruption require recovery and cancel children while ingress survives. FIFO/directory durable files reject before reads. Explicit destructive reset controls and physical GC belong to their dependent V1P09/V1P08 tasks, never implicit module recovery.

Meaningful deterministic/synthetic tests use a compiled native reference child, real private socket/process ownership and temporary checksummed files, signed with an explicit SYNTHETIC fixture key. They cover install/execution/completion, schedule admission/acknowledgement, restart cancellation acknowledgement, state handover, atomic dependency preparation and failed final adoption, failed readiness, required/optional dependencies and disabled required dependency restoration, stale-generation triggers/actions, rollback, disable/re-enable, offline reboot/removal preservation, restart retention, bounded crash/quarantine across reboot, artifact traversal/tamper, missing/corrupt durable files and missing retained state, disk-full versus uncertain writes, concurrent snapshots and real production estate owner startup/recovery/join.
