# V1P09 — cold backup, conservative restore and explicit resets

Entering HEAD: bea1b6f. Final HEAD: cohesive commit containing this record.
Inspected actual config.yaml (Supervisor cold backup), production shutdown,
bootstrap/estate stores, module join/state, timeline/execution/action recovery
and accepted ADR-008/010. Cold backup remains the normal Supervisor mechanism:
stop App, archive /data, restart. No alternate import/archive service or LAN API.

Shutdown now fences availability before lifecycle join, cancels/join children
and catalog, and shares an I/O gate across module storage, coordination and
production catalog writes. Healthy joined shutdown records a bounded stopped-
tree digest checkpoint within three seconds; an unavailable supplemental
checkpoint is logged, never used to drop/reinitialize state. Restore checks any
checkpoint before all boot writes/admission, removes it with directory sync,
then runs existing full signed/checksummed/cross-reference recovery. Missing,
extra, modified or linked files reject a checkpointed restore. Crash recovery
without a checkpoint continues conservative full validation. Normal Supervisor
restore uses the same fixed /data/housefold path; arbitrary relocation is not
an import feature. Prior running work interrupts; unknown actions are retained
without retry; desired disabled/quarantined state and selected version survive;
fresh boot/generation authority is mandatory; replay uses bounded horizons/IDs.

Cleanup uses safe GC. ClearVolatile stops/joins only the selected module's owned
generations then clears cache/temp, preserving persistent/retained state and
uncertainty. Quarantine is not implicitly cleared. FactoryReset requires exact
explicit destructive confirmation, fences/joins owners, writes intent, deletes
only owned contents and requires Supervisor restart. It can discard corrupt
files explicitly, and unlinks owned links without following them. Interrupted
intent remains recovery-required; no automatic deletion resumes. Full HA-admin
UI wiring is V1P03, still dependent on the external V1P05 blocker.
